The bugs we found on ourselves

We went looking, rather than waiting to be caught. The test suite was green through every one of these — which is the point.

Critical · broke the core claim

The approval gate failed open between runs

Approve a rollback once. Start a second run without resetting the bus, and it executed with nobody at the keyboard — recording by: "human" for a decision no human ever made.

GET /decision matched on action name, and action names are not unique across runs.

Fixed on the bus, which is the only place it works: the agent's own stale-id guard lives in process memory and is empty in a fresh process. Reproduced end to end before and after.

Critical · security

The sandbox could read any file on the machine

It blocked sockets, subprocesses and dangerous imports. Nothing stopped open('.env').read().

We proved it by doing it: a diagnostic handed back our live TrueFoundry API key inside its own result, and could write anywhere on disk. Scrubbing the environment is not enough when the secrets are also on disk.

Every path-opening entry point — builtins.open, io.open, io.FileIO, the os file functions — is now confined to the sandbox directory. Nine tests cover the escapes verbatim.

Critical · demo-fatal

The approval card was blank on every live run

It read "no rationale given." The rationale came only from prose in the same turn as the tool call, and GPT-4o fires the call with empty text. A human was being asked to authorise a production rollback with nothing to read.

It looked correct in simulation, because the scripted provider always narrates. Only the real model exposed it.

Fixed structurally: reason is a required parameter on every gated tool, with a fallback to the sandbox verdict if a model ignores it. The card is never blank.

Honesty · the system claiming something untrue

Three ways it lied without failing

It blamed a human for a denial no human made. Kill the bus and the gate fails closed correctly — but the summary read "rejected by the on-call human."

It reported "executed" for an action that failed. Approval is not execution: with the environment unreachable the call returns ok: false and production never changed.

A test was passing for the wrong reason. assert not ok on a 4 GB allocation passed because a bytearray is not JSON-serialisable — not because any limit fired. macOS rejects every memory rlimit. We corrected the claim, not the test.

Also fixed

An environment that rewarded wrong answers

It healed on any version string — rolling back to v9.9.9-never-shipped, or to the bad deploy itself, both reported healthy. /scale accepted -5 replicas. limit=0 returned everything.

An environment that confirms a nonsensical action makes a wrong diagnosis look like a success, which hollows out the whole scenario.

Plus: XSS via agent-written Python in the timeline, and a timeline with no scroll container that pushed the approval button off-screen mid-run. Qodo found seven more across pull requests — including a launcher that would have auto-approved everything while the UI claimed to be gating. All fixed before merge.

How we tested it

227 tests are the floor, not the story.

  • Adversarial: ten sandbox escape attempts, including io.FileIO and os.open bypasses. Ten blocked.
  • Failure injection: killed the bus mid-approval, killed the environment mid-run, kill -9 on the agent. No tracebacks — failures surface as data the model can react to.
  • Concurrency: two agents on one bus. One approval opens exactly one gate.
  • Mutation testing: we broke five load-bearing assertions on purpose and confirmed each was caught. A test that cannot fail is not a test.
  • Hostile input: twelve events carrying <script> and <img onerror> in every field. Zero injections survived.
  • Fresh-clone rehearsal and five-plus live gateway runs, hitting 0.76 every time.

Where TrueFoundry sits

Stated precisely, because precision is the point.

Every model call routes through the TrueFoundry AI Gateway: authenticated, traced, and tagged X-TFY-METADATA per run, so a run on the dashboard maps to its own token spend and latency. A preflight validates the configured model id against the gateway's own catalogue and refuses to start on a mismatch — a bad id fails before the demo instead of during it. Swapping the model is a config change, not a code change.

The gateway is an OpenAI-compatible model router, not an agent runtime. So the harness layer — sandboxed execution, the approval gate, subagents, session survival — is ours, built against a frozen contract and backed by tests. We do not claim TrueFoundry runs the agent loop; it routes and observes every call the loop makes.

The speed of automation, with a human on the one action that cannot be undone — and every safety property is a test, not a promise.
